# Hermes — AI-помощник инвестиционного процессора

Hermes работает поверх действующего «Инвестиционного процессора» и снимает
рутину вокруг согласований и контроля проектов, делая это безопасно для
конфиденциальных данных. Роли и порядок согласования не меняются: согласуют
**CFO и менеджер**, **CEO — наблюдатель**. Hermes не принимает решения за людей.

## Что умеет

- **Вопросы и аналитика в Mattermost.** Сотрудник спрашивает «статус проекта X»,
  «какие заявки ждут согласования», «сводка по портфелю» — Hermes отвечает по
  реальным данным.
- **Согласования в мессенджере.** При переходе проекта в статус «на согласовании»
  ответственные получают карточку с кнопками «Согласовать / Отклонить /
  На доработку», а заявитель — напоминание обновить факт и статус майлстоунов.
- **Напоминания по дедлайнам** майлстоунов (фоновый планировщик).
- **Обновление данных** (факт, статус майлстоунов) через помощника — под контролем,
  по явному запросу (без принятия решений за людей).

## Безопасность (4 столпа)

1. **Единая точка общения с ИИ** — `services/ai_service.py::_chat`. Здесь встроены
   обезличивание и аудит, поэтому они работают во всех сценариях.
2. **Обезличивание** — `services/anonymizer.py`. Перед отправкой во внешний ИИ
   названия проектов, ФИО, коды МВЗ и контакты заменяются на метки
   (`[PROJECT_1]`, `[PERSON_1]`, `[MVZ_1]`, `[CONTACT_1]`), в ответе
   восстанавливаются. Финансовые суммы по умолчанию сохраняются.
   Внутри Mattermost данные идут как есть (доверенная система).
3. **Шлюз MCP** — `app/mcp/`. ИИ не имеет прямого доступа к БД: только строго
   ограниченный набор разрешённых операций (`registry.TOOL_SPECS`). Каждый вызов
   проходит контроль и пишет аудит. Есть standalone MCP-сервер на открытом
   стандарте (`python -m app.mcp.server`, stdio) для внешних ИИ-клиентов.
4. **Сквозное логирование** — структурный JSON (`logging_config.py`) + журнал
   `audit_log` (`services/audit_service.py`). Фиксируется, кто/что/с каким
   результатом сделал и что обезличивание применилось; конфиденциальный текст в
   логи не попадает. Ошибки уходят в служебный канал Mattermost
   (`services/alert_service.py`).

Служебный аккаунт помощника `hermes-bot` (роль `ceo`, read-only) создаётся на
старте. Операции на запись отключены по умолчанию.

## Ключевые эндпоинты

| Метод | Путь | Назначение |
|-------|------|-----------|
| POST | `/api/v1/mattermost/hermes` | Вопрос из Mattermost (slash-команда) → ответ агента |
| POST | `/api/v1/mattermost/actions` | Нажатие кнопки в карточке согласования |
| PATCH | `/api/v1/projects/{id}/status` | Смена статуса (единая логика согласования) |
| PATCH | `/api/v1/projects/{id}/milestones/{index}/status` | Персист статуса майлстоуна |
| GET | `/api/v1/audit/` | Журнал аудита (только CFO) |

## Настройки

Секреты (шифруются в `/data/settings.json`, env имеет приоритет):

| Env / поле | Назначение |
|-----------|-----------|
| `ROUTERAI_API_KEY` + провайдер `routerai` | LLM для агента Hermes (Claude) |
| `MATTERMOST_ALERT_WEBHOOK` | Incoming webhook служебного канала для ошибок |
| `MATTERMOST_COMMAND_TOKEN` | Верификация slash-команд и нажатий кнопок |
| `MATTERMOST_BOT_TOKEN` | Токен бота (DM, карточки) |
| `MATTERMOST_BASE_URL` | URL сервера Mattermost (bot API) |
| `MATTERMOST_INTEGRATION_URL` | Внешний URL бэкенда для callback-ов кнопок |
| `LOG_LEVEL` | Уровень JSON-логирования |

Флаги в файле настроек (переключает CFO):

- `anonymize_enabled` (по умолчанию **on**) — обезличивание перед ИИ.
- `anonymize_round_amounts` (**off**) — округление сумм при обезличивании.
- `ai_enabled` — егресс данных во внешний ИИ (как и раньше).
- `reminders_enabled` (**off**) — фоновые напоминания по дедлайнам.
- `hermes_write_enabled` (**off**) — операции помощника на запись
  (факт, статус майлстоунов). Согласование помощнику недоступно всегда.

## Эксплуатация

- **Мониторинг ошибок:** служебный канал Mattermost (`MATTERMOST_ALERT_WEBHOOK`).
- **Аудит:** `GET /api/v1/audit/` (фильтры `action`, `result`, `actor_type`).
  Полезные `action`: `ai.chat`, `mcp.tool_call`, `hermes.answer`,
  `hermes.approval_card_sent`, `status.change`, `write.fact`, `write.milestone`,
  `hermes.deadline_reminder`.
- **MCP-сервер для внешних клиентов:** `python -m app.mcp.server` (stdio;
  запускается MCP-совместимым клиентом, требует пакет `mcp`).
- **Тесты:** `cd backend && pytest`.

## Порядок внедрения (реализовано поэтапно)

1. Фундамент безопасности — обезличивание + логирование.
2. Шлюз доступа (MCP) + Hermes-аналитик.
3. Согласования в мессенджере — карточки с кнопками + напоминания.
4. Действия на запись + эксплуатация — аудит, обновление данных под контролем.
